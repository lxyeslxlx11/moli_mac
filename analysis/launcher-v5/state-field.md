本增量只沿既有样本和反汇编追踪一个字段。未操作虚拟机/界面、执行官方程序、联网、提权或改变兼容模式。用户补充“双 EXE 均设置 Windows 7 兼容模式”是正常流程的用户提供前提；当前环境状态与效果未验收，该说明不构成新增动态授权。

## 固定来源与结论

样本为 `POLCN_Launcher.unpacked.exe`，1,735,168 字节，SHA256 `601b79565e4ac4c71605744a5087bb24582dde164f417514c74190cd4cdc6e31`。使用既有 GNU objdump `2.47.20260726` 反汇编，重新以独立 PE32 读取器核验指定字节、文件偏移、导入表及相对调用/跳转目标。沿用 REA `6.7.0` / Ghidra `12.1.4` 的 stage3 背景，不新做全样本分析；旧 high-pcode 被截断，以下以限定机器指令和资源结构为依据。

**事实（固定样本，高置信度）**：此前未知的总对象 `+0x1708`，对应子对象 `+0x15ec`，子对象位于总对象 `+0x11c`。它绑定控件 `0x405`，该控件资源文本是“仅刷新通行证”。**解释（高置信度）**：这是该复选框的检查状态整数，不能称为单个位掩码、登录成功标志或认证数据。

## 控件文本的独立定位

既有 REA PE 资源证据 ID：`ev_b7ec0f3b54328ce8e68e1eb5e8ee35e510ef9a4c80911504bb0b6e4e1c25338c`。

- RT_DIALOG `133` / 语言 `2052`；构造函数 `0x40fcba` 的模板参数也是 `0x85`（133）。
- 资源 VA `0x5af6c8`，文件偏移 `0x1a46c8`，长度 `1016`；SHA256 `e297cbefcf050bacfa668feb4f4b6f8da710012f0668dafb256de2526d26170d`。
- 有界 DIALOGEX 解析恰好消费 1016 字节、23 个控件。第 16 项（从 0 计数）ID `0x405` 位于文件偏移 `0x1a49b8`，BUTTON 类 ordinal `0x80`，style `0x58012003`；文本位于 `0x1a49d4`，为“仅刷新通行证”。
- 只保存这一个静态标签和结构元数据，没有保存完整资源或其他控件内容，更没有读取运行时输入值。

## 启动之前的更新顺序及三个读取点

**事实（限定调用链，高置信度）**：`0x410c80` 的启动路径先在 `0x410cfa` 压入 `1`，于 `0x410cff` 调用数据交换函数 `0x42bbec`，之后 `0x410d09` 取得总对象、`0x410d10` 调用启动方法 `0x407a00`。

`0x42bbfa/0x42bbff` 将参数保存为交换上下文首 DWORD；`0x42bc2d` 调用虚表 `+0xfc`。构造虚表在 `0x4b4638` 的该槽内容为 `0x410250`，此方法包含上述 `0x41047c` 的控件绑定。辅助函数 `0x4341b7` 据上下文首 DWORD 选择读控件还是写控件，参数 1 进入读取并写字段路径。这补齐了“构造初值 → 启动前从控件读取 → 启动方法读取字段”的正常静态顺序。

调用方 `0x410cff` 之后没有检查返回值再调用启动方法；因此不能把“前一调用存在”说成所有运行时数据交换均成功，更未观测当前控件值或实例身份。

| Code 11 条件 | `+0x1708 == 0` | `+0x1708 != 0` |
| --- | --- | --- |
| `0x407fd8` / `0x407fdf` | 进入 CG 资源参数生成段 | 跳 `0x408391`，略过该段 |

上述三处直接读取都是完整 DWORD 与零比较，没有对该字段作单独位掩码测试。非零分支仍会经过 v4 已定位的共享映射公共段；“仅刷新通行证”的网络语义和实际凭据处理不在本次调查范围，未据标签推导协议。
