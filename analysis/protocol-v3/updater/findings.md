## 五槽消费规格增量

**事实**：`0x401210` 从全局 `0x411410` 读取文本指针，构造字符串及输入流；`0x40127d/0x401283/0x401289/0x40128f/0x401295` 连续调用导入的 `std::operator>>(istream&, char*)`。业务解析是五次流提取，不能直接写成已还原完整的操作系统 argv 规则。该全局指针的完整框架赋值链仍未追踪。

| 槽位 | 原始 EBP 缓冲区 | 已观察的消费者用途 | 边界与状态 |
| --- | --- | --- | --- |
| 1 | `-0x138` | `atoi`（`0x4012a4`）后进入 `OpenProcess` 第三参数 | **事实**；不能命名为已正确识别的父进程 PID。生产者使用 `GetWindowThreadProcessId` 返回值，另有实参异常 |
| 2 | `-0x338` | CString，`0x4012fa` 把 `|` 换为空格，随后进入 `OpenURL` | **事实**：下载定位符；未取得或验证清单、响应或 URL 政策 |
| 3 | `-0x538` | CString，`0x401310` 同样替换；用于删除/复制目标，以及再次启动字符串 | **事实**：本地替换/再次启动目标；路径引用、失败回滚和实际启动均未验证 |
| 4 | `-0x238` | `atoi`（`0x4012af`）保存到 `EBP-0xd54`，参与累计字节数乘 100 后的无符号除法（`0x4015f5`）及显示 | **事实**：进度分母和显示值；“预期下载总字节数”属**推测**，审阅循环未见最终长度相等校验 |
| 5 | `-0x38` | `_strupr`（`0x40187d`），与 `.new` 计算结果大写化后比较（`0x401897`） | **事实**：预期产物摘要文本；MD5 身份仍为**推测**，不是签名或来源认证证明 |

**事实**：只看到槽 2、3 的竖线还原；字面量 `|` / 空格位于 VA `0x40b8ac/0x40b8b0`，文件偏移 `0xb8ac/0xb8b0`。结合生产者“空格变竖线”，可确认这是文本代换约定。它没有提供保留字面竖线的转义规则。

**事实**：数字槽经 `atoi` 后以 `TEST/JBE` 检查零。该指令组合不能描述为“只接受正整数”：`TEST` 清除进位标志，负数对应的非零位模式也不会在该检查被拒绝。当前解析块未观察到流宽度限制、完整数字语法/溢出检查、流错误状态检查或第六槽拒绝。

**待验证**：默认流空白分类、引号、超长输入、缺槽、额外槽、负数、整数溢出及非 ASCII 文本的完整运行行为。独立实现可自行采用有界输入和严格数字语法；这属于原创接口约束，不能伪称原程序等价规则，也不应复制原路径中未检查错误的行为。

## 已观察的更新及再次启动链

1. **事实**：`OpenProcess` 调用位于 `0x4013ce`（IAT `0x40b014`），此前依次压入槽 1、`0x1f0fff`、0。按标准 API 参数顺序相当于访问权限 0、继承标志 `0x1f0fff`、进程 ID 槽 1。随后 `0x4013d7` 用返回句柄及无限等待值调用 `WaitForSingleObject`；这段没有检查返回结果。结合生产者的线程 ID 来源，此路径含静态异常，不能宣称已正确等待父进程。
2. **事实**：固定临时名 `POL_Launcher.pak`（VA `0x40b878`）及 `POL_Launcher.new`（`0x40b88c`）。`0x40147a→0x409452` 是 Ghidra 解析为 `CInternetSession::OpenURL` 的跳板，参数来自槽 2，flags 为 `0x84000002`。`0x4014c1→0x409446` 查询 HTTP 状态；查询成功且状态大于等于 400 进入错误路径，查询失败或状态小于 400 均继续。不能写成“仅 HTTP 200 才接受”。未发出实际请求。
3. **事实**：下载循环请求最多 `0x3ff` 字节，根据读取返回值决定终止，并写入 `.pak`。槽 4 用于进度运算。局部循环未见最终长度等于槽 4 的检查。
4. **事实**：`.pak` 经 `0x4030e0/0x402d60/0x402160` 等辅助函数读取或转换，以 `0x400` 大小分块写入 `.new`；之后删除 `.pak`。**待验证**：精确容器、压缩格式、校验和错误规则。扩展名和 zlib 相关字符串不足以确认为某种完整格式。
5. **事实**：`0x401845→0x404310` 处理 `.new` 文件，后者循环读取 `0x400` 字节，调用 `0x4040a0`，再调用 `0x404160` 产出待比较文本。该函数初始化 `67452301/efcdab89/98badcfe/10325476` 四个常量。**推测**：与 MD5 初始化及增量结构一致；本轮没有复核完整轮函数、填充、字节序和输出格式，也没有运行测试向量。
6. **事实**：摘要归一化比较等于零后，执行删除目标（`0x4018b2`）、`CopyFileA(.new, 目标, FALSE)`（`0x4018cd`）、删除 `.new`（`0x4018dd`）。此局部块未检查删除/复制返回值，不具备已验证的原子替换或回滚保障。比较不等分支删除 `.new` 并走错误清理。
7. **事实**：再次启动字面格式 `%s ID:%d` 位于 VA `0x40b724` / 文件偏移 `0xb724`，xref `0x401968`；字符串槽为目标路径，ID 值来自 `0x401913` 的 `GetWindowThreadProcessId(hWnd, NULL)` 返回。`0x4019a4` 调用 `CreateProcessA`。结果被检查并分开记日志，但成功与失败两支均压入 0 后跳至公共 `exit`（`0x401abb`）。因此退出码 0 不能作为再次启动成功验收条件。详见 [生命周期复核](lifecycle/lifecycle-summary.md)。
