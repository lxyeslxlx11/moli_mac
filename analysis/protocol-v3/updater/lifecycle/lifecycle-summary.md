## 原创逻辑摘要

观察到的主线为：参数检查 → 调用进程打开/等待 API → 下载到 `.pak` 并显示进度 → helper 分块输出 `.new` → 删除 `.pak` → 比较 `.new` 的候选摘要与第 5 项 → 相等时删除目标、复制 `.new`、删除 `.new` → 构造目标加 `ID` 的命令行 → 再次启动 → 退出。摘要不匹配时清理 `.new` 并返回错误退出码。

以上是更新器的文件和进程逻辑，不能用于推导游戏消息帧、账号登录、加密、认证或浏览器/小程序的网络兼容性。

## 未证实项与下一验证

1. **待验证：等待对象是否有效。** 首个整数的上游来源为 `GetWindowThreadProcessId` 返回值；消费端还存在上述 OpenProcess 参数顺序异常。现有静态证据不能保证取得有效进程句柄或成功等待，且等待返回值在紧接路径未被检查。下一步仍可离线复核上游 ID 来源、IAT 与调用约定；实际运行结果需另行申请具体动态授权。
2. **待验证：摘要算法与 `.pak` 变换。** 可在已授权范围继续静态分析 `0x404310`、`0x402160` 及其被调用函数，独立形成格式规格；不能凭字符串或库诊断认定网络协议。
3. **待验证：异常路径完整性。** 本证据覆盖所列主消费路径及部分错误尾部，不穷尽全部异常处理或文件系统失败情况。当前没有替换失败、路径含空格、文件锁定、权限不足等运行结果。
4. **待验证：再次启动目标的 ID 消费。** 可由父任务将 `%s ID:%d` 对接登录器的已有 ID 参数消费者证据；即使吻合，也只是本地进程交接，不是服务器会话或身份认证证明。
