# Original x86 debugger check

This media contains only the reviewed original fixture, its original CDB command file and this note. It contains no game files or credentials. The fixture was previously checked with REA and raw PE bytes; its executable is unchanged.

Verify `moli-diagnostic-fixture.exe` SHA256 `01588841278dcb7360c91333f0f7c5ec81aec84625ca274be54ad9011aaf10eb` before execution. It creates only its own PID-named 64-byte mapping, never accesses mapping bytes, and exits normally after roughly 1.75 seconds plus startup. It has no network, files, child processes or argument-content handling.

First run the fixture normally and inspect its exit code. Then use the installed Microsoft ARM64 CDB with the supplied command file, a local-only symbol directory, ignored symbol-path environment and no shell/SQM. The fixture has ASLR enabled; derive its actual image base from the executable entry-point pseudo-register minus the verified entry RVA `0x1270`. Compare that base with the loaded-module list, the seven actual return-site RVAs, the target exit code and return to the PowerShell prompt. Stop on unexpected debugger errors and inspect the actual state before retrying. No automatic memory dump, process kill, exception-policy override or persistent debugger registration is included.

The command file uses software breakpoints only in this original fixture and auto-continues after printing the instruction-pointer RVA. It does not read argument registers, stack, command-line text, mapping names or contents. The seven API labels come from the previously reviewed fixed call sites; this is a fixture return-site test, not an arbitrary-program API-entry collector. It records no timing and cannot satisfy the existing timed trace contract or prove general collector privacy.

The later command-file media adds the original `run.cmd` runner. Verify all media member hashes before use, then invoke `cmd.exe /d /c D:\run.cmd`. The runner fixes the already-verified ARM64 CDB path and derives only this media's script/fixture paths; it has no supplied user arguments, downloads, profile changes or process-kill operation. `/d` disables CMD AutoRun. It echoes the debugger exit code after return. The long interactive CDB command suffered missing characters and failed before launching the fixture, so that failure is retained separately and is not an x86 compatibility result. The new runner still needs actual Windows verification.

Passing this check proves only the tested x86 fixture/debugger behavior on the current Windows ARM64 VM. It does not establish game protocol, authentication or compatibility.

Microsoft documents the [executable-entry pseudo-register](https://learn.microsoft.com/en-us/windows-hardware/drivers/debuggercmds/pseudo-register-syntax), [CDB options](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/cdb-command-line-options) and [ARM64/x86 debugger context](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/debugging-arm64).
